# Changing Resolution Training Plan

This plan tracks the clean-latent 480p -> 720p route for LightX2V
`changing_resolution`.

## Goal

Train a clean latent resizer that can replace LightX2V's fixed interpolation
inside changing-resolution inference.

The working contract is:

```text
z0_lr or x0_pred_lr -> z0_hr
```

For the current 480p -> 720p setting:

```text
RGB:    480 x 832  -> 720 x 1248
latent:  60 x 104  ->  90 x 156
scale:  1.5x spatial
```

## Data

The current 1k source set is generated by Wan2.1 at 720p from Self-Forcing
video prompts.

For every generated 720p video:

```text
z0_hr = Wan VAE encode(video_720p)
z0_lr = Wan VAE encode(resize(video_720p, 480 x 832))
```

The training artifact is the sharded LMDB dataset:

```text
data/changing_resolution/lmdb_480p720p_1k
```

Each row stores:

```text
z0_lr, z0_hr, prompt, meta
```

## Stage 1: Residual Resizer Baseline

Use the existing `WanCleanLatentResizer` without changing model structure.

Structure:

```text
z0_lr
  -> Conv3D 16 -> 256
  -> ResBlock3D x4
  -> trilinear feature resize to target H/W
  -> ResBlock3D x4
  -> Conv3D 256 -> 16 residual
  -> trilinear(z0_lr) + residual
  -> pred_z0_hr
```

Purpose:

```text
Verify whether a learned residual around trilinear interpolation improves over
the stock LightX2V interpolation baseline.
```

Keep the model conservative:

```text
hidden_channels: 256
num_res_blocks: 8
residual_skip: true
scale_factor: 1.5
```

Primary acceptance checks:

```text
1. Training loss decreases stably.
2. Low-frequency loss stays bounded, meaning pred_z0_hr still decodes to the LR source when downsampled.
3. Comparison videos show trained720 sharper or more temporally coherent than interp720.
4. The model does not introduce strong flicker, texture crawling, or broken motion after LightX2V bridge insertion.
```

Stage 1 output:

```text
outputs/changing_resolution_clean_480p720p_stage1_lmdb/latest.pt
outputs/changing_resolution_clean_480p720p_stage1_lmdb/step_*.pt
outputs/changing_resolution_clean_480p720p_stage1_lmdb/best_val.pt
outputs/changing_resolution_clean_480p720p_stage1_lmdb/metrics.jsonl
```

Default Stage 1 run:

```text
train/val split: 95% / 5%, deterministic by seed
max_steps:       10000 for the first checkpointing pass
eval_every:      1000
effective batch: 8
best model:      lowest EMA validation loss
```

If the 10k checkpoint improves over interpolation in comparison videos, extend
the same run to 20k steps before changing the model structure.

## Stage 2: Learned Feature Upsampler

Start only if Stage 1 beats interpolation in visual comparisons.

Replace the current fixed feature resize block with a stronger learned
upsampling module while keeping the residual skip:

```text
LR feature blocks
  -> learned feature upsample module
  -> HR feature blocks
  -> output residual
```

Candidate module:

```text
trilinear feature resize + gated Conv3D residual refinement
```

Reason:

```text
It is stronger than the current residual-only correction, but still stable with
1k samples and a fixed 1.5x target.
```

Avoid large attention/U-Net changes until Stage 1 gives a clear baseline.

## Stage 3: Conditioning And Scale Generalization

Consider only after Stage 2 is stable.

Possible additions:

```text
prompt/text conditioning
sigma or step conditioning for x0_pred bridge mismatch
multi-resolution training
larger datasets
DDP training
```

These are not Stage 1 requirements.

## Evaluation Protocol

Use two separate evaluation suites.

### Operator Compare: With Reference

Use the held-out LMDB validation split. This is the only suite with a true
reference target:

```text
lr480_decode      = decode(z0_lr)
ori720_decode     = decode(z0_hr)
interp720_decode  = decode(trilinear(z0_lr))
trained720_decode = decode(model(z0_lr))
```

Metrics compare `interp720_decode` and `trained720_decode` against
`ori720_decode`. The default metric set follows
`mit-han-lab/x-attention/eval/HunyuanVideo/similarity.py`:

```text
PSNR, SSIM, LPIPS
```

This answers:

```text
Is the learned clean-latent resize operator better than interpolation?
```

Run:

```bash
TOTAL_SAMPLES=32 GPU_IDS=0,1,2,3 \
bash changing_resolution/scripts/eval/run_clean_480p720p_operator_compare_multigpu.sh
```

### Chain A/B Compare: No Reference

Use the actual LightX2V changing-resolution inference chain. This suite has no
ground-truth target, because native 480p and native 720p generations follow
different trajectories.

Compare only:

```text
interp720  = LightX2V changing_resolution + fixed interpolation
trained720 = LightX2V changing_resolution + trained clean latent resizer
```

This answers:

```text
Does replacing the clean-latent resize operator improve the actual generation chain?
```

Run:

```bash
TOTAL_SAMPLES=16 GPU_IDS=0,1,2,3 \
bash changing_resolution/scripts/eval/run_clean_480p720p_chain_ab_compare_multigpu.sh
```
